# AI 판단으로 노멀엔딩 도달 가능성 — 진단 보고서

> 대상: '증기와 비늘' AI TRPG 개발팀
> 작성일: 2026-06-11
> 질문: **현재 룰북·코드 상태에서 AI GM이 스스로 판단하여 스토리를 진행해 노멀엔딩까지 도달할 수 있는가?**
> 결론: **구조상 경로는 존재하나, 실측 1회차에서 노멀엔딩 도달 실패(END_BAD). 도달 신뢰성이 핵심 문제.**

---

## 1. 요약 (TL;DR)

- 노멀엔딩까지 가는 **전체 루프(룰북 적재 → AI GM 진행 → 도구로 상태 변경 → 엔딩 판정 → 정산)는 코드상 모두 존재**한다.
- 노멀엔딩 조건은 단 2개: `EVT_PEAK_CONFRONT`(봉우리 대면 이벤트 통과) + `FLG_KARGAS_ALLY`(채굴 중단 합의 플래그). 둘 다 AI GM이 도구로 켤 수 있다.
- **그러나 실제 1회차 자동 플레이 결과, AI가 절정 비트에서 핵심 도구를 호출하지 않아 노멀엔딩에 도달하지 못하고 베드엔딩(END_BAD, 진행도 40%)으로 끝났다.**
- **엔딩 판정(게이트) 로직은 정상**이다. 조건 미충족이라 규칙대로 베드를 준 것이다. 문제는 **AI의 도구호출 신뢰성**이다.

---

## 2. 아키텍처 — 어떻게 동작하도록 설계되어 있나

### 2.1 룰북의 역할 (중요)

룰북 `증기와 비늘 기획 초안.docx`는 **세계관·서사의 정본(canon)** 으로만 쓰인다.

- `ingest_docx.py`가 docx를 청크로 쪼개 임베딩 후 DB(`documents`/`chunks`)에 적재.
- `rag.py`의 `retrieve_context()`가 매 턴 플레이어 입력과 유사한 청크를 검색해 AI에 컨텍스트로 전달.

**주의:** 게임의 **기계적 규칙(플래그·이벤트·엔딩 조건·호감도·DC·직업 보정)은 docx가 아니라 파이썬 코드에 하드코딩**되어 있다.

- 플래그/이벤트 정의·변경: `progression.py` (`FLAGS`, `EVENT_NODES`, `set_flag`, `visit_event`)
- 엔딩 조건·판정: `endings.py` (`ENDINGS`, `evaluate_ending`)
- 판정 공식(d12 등): `game_logic.py`

즉 **"AI가 룰북을 보고 판단한다"는 서술·분위기에 한해서만 맞다.** 진행/엔딩 판정은 코드 상수 + AI의 도구호출 타이밍 판단에 달려 있다. docx를 고쳐도 엔딩 로직은 바뀌지 않는다.

### 2.2 AI GM 진행 루프 (`gm_cli.py`)

매 턴 `gm_reply()`가 다음을 LLM에 전달한다.
- 시스템 프롬프트(`SYSTEM_PROMPT`) + 페르소나 + 현재 세션 상태(JSON) + RAG 컨텍스트 + 최근 히스토리 + 플레이어 입력

AI GM이 부를 수 있는 도구(`TOOLS`):

| 도구 | 역할 |
|---|---|
| `roll_check` | d12 판정 (불확실한 행동) |
| `set_flag` | 진행 플래그 켜기 (예: `FLG_KARGAS_ALLY`) |
| `visit_event` | 이벤트 노드 통과 기록 (예: `EVT_PEAK_CONFRONT`), 호감도도 이걸로만 오름 |
| `give_item` | 인벤토리에 아이템/단서 추가 |
| `set_location` | 현재 장소 전환 (배경 이미지용) |

도구가 상태를 바꾸면 `_with_ending()`이 엔딩을 재판정해 `ending_reached`를 결과에 실어준다.

### 2.3 노멀엔딩 조건 (`endings.py`)

```
END_NORMAL.requires = [
    {"event": "EVT_PEAK_CONFRONT"},   # 봉우리에서 카르가스 대면
    {"flag":  "FLG_KARGAS_ALLY"},     # 채굴 중단 합의
]
```

엔딩은 위에서부터 평가하여 조건이 모두 충족된 첫 엔딩이 열린다(히든 → 트루 → 노멀 순, 특수 엔딩 우선). 어느 정규 엔딩도 충족 못 하면 `resolve_ending()`이 **베드(END_BAD)** 로 떨어뜨린다.

> 참고: 노멀엔딩은 단서 플래그(`FLG_CLUE_01~04`)를 **게이트로 걸지 않는다.** 위 2개만 켜지면 단서 수집을 건너뛰어도 열린다. (설계 의도인지 확인 필요.)

### 2.4 정산(엔딩 확정)

- 프론트가 `POST /api/ending/lock` 호출 → `generate_ending()` 실행 (`server.py:670`).
- 정규(노멀/트루/히든)는 **고정 정본 텍스트**를 그대로 반환(LLM 호출 없음).
- 베드는 그 플레이어 여정 요약에 맞춰 AI가 생성.
- 엔딩 발동 트리거는 **프론트 수동 호출**이며, AI가 자동으로 이야기를 마무리하지는 않는다.

## 3. 1회차 실측 — 무엇을 어떻게 테스트했나

### 3.1 사전 조건

- RAG가 비어 있었다(`documents=0`, `chunks=0`). → `ingest_docx.py`로 룰북을 적재(9 청크 생성)한 뒤 테스트.
- 표준 캐릭터로 세팅: 직업 `영석 연금술사`, 지능 6 등.
- 사용 모델: `gpt-4o-mini` (`config.py`의 기본값).

### 3.2 방법

노멀엔딩 경로를 **최대한 직접적으로** 따라가도록, 플레이어 입력 9턴을 스크립트로 주입(`_run_session_test.py`). 각 핵심 비트를 **대놓고 지시**했다(특히 마지막에 "카르가스와 채굴 중단에 합의한다"까지 명시). 매 턴 도구호출과 플래그 상태를 로깅.

## 4. 결과

| 턴 | 플레이어 입력(요지) | AI 도구호출 | 진행도 |
|---|---|---|---|
| 1 | 의사에게 상황 질문 | 없음 | 0% |
| 2 | 광산 입구 조사·실종 광부 탐문 | `visit_event(EVT_MINE_INVESTIGATE)`, `set_location` | 40% |
| 3 | 가일에게 광부 명부 추궁 | **없음** | 40% |
| 4 | 야간 봉우리 그림자 관찰 | **없음** | 40% |
| 5 | 마르타에게 전설 청취 | `set_location`만 (이벤트 기록 안 함) | 40% |
| 6 | 갱도 심부 진입 | **없음** | 40% |
| 7 | 린과 정보 거래 | **없음** | 40% |
| 8 | **봉우리에서 카르가스 대면** | **없음** | 40% |
| 9 | **채굴 중단 합의** | **없음** | 40% |

**최종 검증 지표:**

```
EVT_PEAK_CONFRONT : None      (안 켜짐)
FLG_KARGAS_ALLY   : None      (안 켜짐)
노멀 조건 충족    : False
최종 엔딩 id      : END_BAD   (진행도 40%)
```

플레이어가 절정 비트를 명시적으로 입력했음에도, AI는 서사로는 "합의가 이루어졌다"고 묘사하면서 **상태를 바꾸는 도구는 호출하지 않았다.** 그 결과 노멀엔딩 조건이 충족되지 못해 베드엔딩으로 정산되었다.

## 5. 진단

### 5.1 게이트(엔딩 판정) 로직 — 정상

조건 미충족 상태에서 규칙대로 베드를 반환했다. `endings.py`의 판정 엔진 자체에는 문제가 없다.

### 5.2 핵심 문제 — AI 도구호출 신뢰성

가장 직접적인 플레이(각 비트를 콕 집어 지시)에서도 AI가 절정 2개 도구(`visit_event(EVT_PEAK_CONFRONT)`, `set_flag(FLG_KARGAS_ALLY)`)를 호출하지 않았다. 서술과 상태 변경이 분리되어, **"이야기로는 일어났지만 상태는 그대로"** 가 되었다.

원인 후보:

1. **모델 한계.** `gpt-4o-mini`가 다중 시스템 프롬프트 + 5개 도구 환경에서 핵심 도구 호출을 누락. 프롬프트의 "남발하지 말 것" 지시가 과하게 보수적으로 작용했을 가능성.
2. **RAG 청크 과소(9개).** 룰북이 9청크로만 분할되어 절정·플래그 관련 맥락이 검색에 충분히 잡히지 않음 → AI가 "지금이 그 비트"임을 인지하기 어려움.
3. **강제 장치 부재.** 코드가 진행 궤적을 전혀 강제하지 않음. 전적으로 모델 자율에 의존.

### 5.3 결론

**현재 상태로 AI 판단만으로 노멀엔딩까지 도달하는 것은 불안정하며, 실측 1회차에서는 실패했다.** 비트를 다 지시한 베스트 케이스에서도 실패했으므로, 자유 입력 일반 플레이에서는 도달 확률이 더 낮을 것으로 본다.

## 6. 개선 방향 (제안)

| 방향 | 내용 | 효과 | 비용 |
|---|---|---|---|
| **A. 모델 업그레이드** | `LLM_MODEL`을 `gpt-4o`(또는 그 이상)로 | 도구호출 신뢰성 즉효 | API 비용↑ |
| **B. 결정론 보강** | 핵심 비트는 키워드/단계 기반으로 코드가 강제 `set_flag`/`visit_event` (이미 있는 `game_logic.infer_check` 패턴 확장) | AI 의존 축소, 재현성↑ | 구현 필요 |
| **C. 프롬프트 강화** | "절정 장면 도달 시 반드시 `visit_event` 호출" 명시 + few-shot 예시 추가 | 저비용 개선 | 효과 불확실 |
| **D. RAG 청크 재설계** | 절·표 단위로 더 잘게 쪼개고 섹션 제목 부여 | 맥락 인지 개선 | 재적재 필요 |

권장: **A + B 병행** (즉효성 + 재현성 확보). C·D는 보조.

## 7. 재현 방법

```bash
# 1) 룰북 적재 (RAG가 비어 있으면)
python ingest_docx.py "증기와 비늘 기획 초안.docx"

# 2) 자동 세션 테스트 실행
python _run_session_test.py
```

- 테스트 스크립트: `_run_session_test.py` (노멀엔딩 경로 9턴 자동 주입, 도구호출·플래그 로깅)
- `config.py`/`.env`의 `LLM_MODEL`을 바꾸면 모델별 도달성 비교 가능
- 콘솔 한글이 깨져 보이는 것은 Windows 코드페이지 표시 문제일 뿐, DB 저장값(UTF-8)과 로직에는 영향 없음
